# Private observation store

`src/store.ts` implements `augmentor-observation/1` as diagnostic read models. It never owns Pi conversation state, resumes a request or executes a tool. See [Harness qualification](../../docs/AUGMENTOR-HARNESS.md) for lifecycle, privacy and open performance gates.

Events have stable UUIDs, ordered per-session `seq`, timestamps, kind, optional turn/request correlations, metadata and payload coverage. The counter is reserved atomically before append. Clearing or expiry preserves the counter. Forward and backward pages use exclusive sequence cursors, up to 500 records. Native session history remains untouched.

`src/journal-index.ts` keeps a derived byte-offset index beside each authoritative `events.jsonl`. A 40-byte entry contains sequence, original byte offset/length, time and a checksum; it contains no body text. The private manifest binds the index to source/index file identities, nanosecond modification/change times and sizes. Valid persisted indexes support reopened readers without scanning the source journal. Missing, changed or damaged derived files rebuild by streaming the source. Complete corrupt records fail with the original history preserved; only an incomplete final frame is discarded. Indexes never authorize or replay an operation. The store caches at most 32 index helpers and holds no persistent file descriptors.

`observation.list` accepts an optional `query` of up to 256 characters and 16 whitespace-separated literal terms, matched case-insensitively against the retained metadata JSON. It excludes payload bodies and native/display history. Search scans at most 1,000 records or 512 KiB per call, except that one larger first record can exceed that byte window. All pages reserve transport headroom below 1 MiB; an individually oversized matching record returns an error rather than silently disappearing. `nextBeforeSeq`/`nextAfterSeq` refer to the last scanned record, including when the page has no matches. Continue in the requested direction while `hasMore`; these cursors are null when no record was scanned. `scanned`, `totalRecords`, `journalBytesRead` and `coverage` expose the scope. Results remain in chronological order. There is no inverted text index; literal search still reads each candidate record within its bounded scan window.

Full structured payload retention is explicit opt-in. Bodies are private JSON files with known credential fields redacted and SHA-256 over the stored UTF-8 body. Retrieval returns bounded text chunks, `units: utf8-bytes`, `nextOffset` and `hasMore`; clients concatenate text and parse only after the last chunk. A cursor inside a multi-byte character is rejected. Very small pages may advance by one complete character. Missing or expired payloads return `available: false`.

Default retention is 14 days and 512 MiB. Payloads are evicted before metadata. Derived index/manifest bytes count against this budget and are removed with an evicted journal. Individual bodies cap at 32 MiB or half the budget. Expiry uses the index's minimum timestamp, including out-of-order event times, and streams an atomic journal replacement when necessary. Crash-tail recovery and owned temporary-file cleanup are local storage repairs. One runtime owner must hold the profile; the IPC listener is acquired before construction. The 100,000-record fixture verifies bounded warm/reopened indexed pages; native/display history indexing, payload search, full context provenance and representative live/installed performance remain delivery gates.
