# Manual Pi compaction

The original DSH **Compact** menu row and bare `/compact` now call the existing Pi 1.1.0 `AgentSession.compact()` API. They use the conversation's explicit model and sole session owner. No prompt is admitted, no second loop is created, and no ordinary user/assistant turn is fabricated. The original supplier row, icon, grouping and CSS are reused without supplier changes. Context retains the copied Apache-2.0 dsh-context dashboard; all original MIT/Apache notices remain intact.

A private `augmentor-compactions/1` ledger saves a unique request/conversation/model identity before asynchronous owner loading. A duplicate identity only returns its receipt, including after restart; it never reruns the operation. Model mismatch, active work, owned jobs, armed goal continuation and conflicting shared configuration refuse admission. Compaction pauses waiting prompts. They remain paused after success, failure, cancellation or acknowledgement; continuation is explicit. Model/thinking changes, branching, context repair, new prompts/jobs and goal changes are blocked for that conversation while compacting or while an unknown receipt is unacknowledged. Shared MCP/model/reasoning configuration and prompt improvement cannot overlap the live compaction lease.

Stop targets the owning conversation, aborts Pi's public compaction controller and retains the lease until Pi settles. The public start event closes the race where Pi awaits its ordinary `abort()` before creating the summary controller. Stop during supported extension preparation and provider streaming is qualified with the actual SDK. A summary saved before cancellation takes precedence over a late cancellation request. Settlement checks newly appended native compaction entries and current branch membership; an SDK rejection alone is not proof that no summary was saved. SDK completion and verified native commit are reported separately. A crashed in-flight operation becomes **unknown**, blocks new work and is never replayed. The existing original disclosure components expose explicit acknowledgement after native inspection; acknowledgement retains the unknown result and never retries it. Malformed or unwritable receipts fail closed. The bounded ledger retains up to 256 operation identities and currently has no pruning/export management UI.

Default Pi summaries invoke the public stream function directly rather than Agent's ordinary payload/message hooks. The observation wrapper composes the public summary request-option hooks and observes the public repeatable `result()` promise without consuming, replacing or replaying the stream. Each observed summary request has its own ID, `purpose: manual-compaction` and operation ID; it never inherits an ordinary turn/request identity. Effective credential-redacted payloads follow the existing opt-in retention policy. Parsed summary provider events are bounded to 8 MiB per request, with disabled/partial coverage explicit. Reported normalized usage and monotonic request duration are recorded; first-token time is not established for this path. Pi may make multiple summary requests, particularly when splitting a turn. Unsupported custom stream adapters may omit payload/provider hooks and have explicitly limited coverage.

Saved native entry IDs, SDK estimated tokens before/after, SDK returned/rejected status and cancellation are recorded separately from the summary request. The original dashboard counts confirmed summaries and gives distinct attempt details for aborted or unconfirmed ends. Its latest request composition can be the **summary input before the saved compaction boundary**; the existing coverage notice says so. Neither that input nor the SDK post-compaction estimate proves the next effective provider context. The next ordinary request supplies that evidence. Source native/display originals are preserved; the SDK summary changes the model-visible projection.

This first binding uses Pi's default summary instructions and recent-context policy (20,000 estimated tokens retained at the tested default). Bare `/compact` is an operation; inline slash completion remains editable text. Arguments/custom instructions are not exposed yet. An empty, already compacted or too-small conversation may be refused by Pi before any provider request; its failed attempt remains inspectable. Admission confirms before the owned command span is consumed; refusal or a changed conversation/draft preserves the text. Lost transport replies become unconfirmed and are never retried automatically. Busy/Stop, draft guards, receipt disclosure and Context occupy the existing original seats; no supplier layout is redesigned.
