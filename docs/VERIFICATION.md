# Linux release 0.1.0 verification

Recorded 2026-09-05 on MX Linux 25.2 KDE/Wayland. Pi packages: 0.85.1. Node: 24.19.0. These are Linux results; browser-extension implementation remains deferred.

Automated checks: `npm run check`; `npm test` (19 reported tests) (real Pi SDK with deterministic local model server); `npm run test:native` (31 tests, Qt offscreen). Detailed live evidence is generated locally under ignored `outputs/`; it is not included as user session data in the release archive.

Initial failed desktop test attempts exposed both a stale accessibility address and a test driver that blocked Qt while waiting for AT-SPI. The application resolves the current accessibility bus; the corrected test keeps Qt's event loop responsive. A subsequent CLI-launched native app established the desktop lock needed for browser dispatch, and the complete desktop check passed.

Limitations retained from the agreed scope: no generic GUI input, portal screen capture, dedicated OS-setting adapters, automatic self-update, cross-distro certification or ResonantOS integration. Browser dispatch is verified as dispatch only. DSH historical conversations remain in the original app. Full tool/conversation content may persist in Pi sessions and the private display journal; local route labeling is not runtime egress enforcement.

Shortcut correction, 2026-09-06: the Ctrl+Hangul binding was stored but KDE reported `isActive=false`; direct `invokeShortcut` still toggled the window, so that earlier check did not validate keyboard activation. Both settings and desktop installation now send SetPresent | NoAutoloading (6), including rollback. See [KDE flag definitions](https://github.com/KDE/kglobalaccel/blob/master/src/kglobalaccel_p.h). Targeted shortcut tests pass. `python3 scripts/shortcut-proof.py` injects Linux Ctrl+Hangul key events through ydotool into the Wayland session, verifies KDE is active and observes Pi hidden → shown → hidden, with the legacy binding unchanged. This is synthetic keyboard-event evidence, not a physical Fn-key measurement.

Clipboard templates, 2026-09-06: Prompt Library includes Insert clipboard at the editor cursor. Saved files retain `[clipboard]`; choosing a slash prompt substitutes a single snapshot of the text clipboard, preserves multiline/Unicode content and does not send. Empty/non-text clipboards leave the draft intact. Native tests cover keyboard and mouse choice, undo, save/reopen, stale picker responses and clipboard changes after insertion. All 37 native tests pass. `scripts/clipboard-proof.py` exercises the real isolated Pi prompt store plus Qt UI using the rewrite example, with results in `outputs/clipboard-proof.json` and the visually inspected `outputs/prompt-library-clipboard.png`. No model request is needed for template expansion.

Message actions, 2026-09-06: Copy is available for user and assistant text. Idle assistant replies can branch; the latest user input can be edited and resubmitted into a separate revision with the original chats retained. Runtime tests verify exact context boundaries, earlier tool results, inherited policy/model, stale/invalid/busy targets, caller-ID deduplication and cold restart. All 24 runtime tests and 46 native tests pass. `scripts/message-actions-proof.py` drives the actual Qt controller and local Qwen through two source turns, branches from the earlier reply, copies both roles and edits/resubmits. Qwen retains ORCHID instead of the excluded later MAGNOLIA, then answers ORCHID! to the revised input. Both parent journals remain byte-equivalent in the checked history response. Evidence: `outputs/message-actions-proof.json` and visually inspected `outputs/message-actions.png`.

Message action icons, 2026-09-06: Copy, branch and edit use bundled SVG assets in 24-pixel targets, tinted to the current accent and rendered at display scale through Qt’s existing SVG image plugin. Hover tooltips and image alternative labels retain the action names. All 46 native tests pass, including the updated rendered-icon click and tooltip check. Dark and light 2× previews were inspected (`outputs/message-icons-dark.png`, `outputs/message-icons-light.png`).

Icon sizing adjustment, 2026-09-06: reduced all message action icons from 24 to 12 logical pixels and rotated the branch SVG 90 degrees clockwise around its centre. The existing seven message-action tests pass, including clicking the smaller rendered icon and displaying its tooltip. `outputs/message-icons-small.png` was visually checked.

Icon hover descriptions, 2026-09-06: adjusted message icons to 14 logical pixels (approximately 20% above 12), retaining the clockwise branch rotation. Mouse tracking and always-show tooltips make descriptive help available over each icon. All seven message-action tests pass; Qt mouse-move checks, without injecting tooltip events, displayed the Copy, Branch and Edit descriptions.

Compact hover labels, 2026-09-06: Copy, Edit and Branch in a new chat replace the longer descriptions. A translucent popup paints a rounded dark-grey box with white text, independent of desktop tooltip styling. The seven message-action tests pass; mouse-move checks verify all three labels appear and dismiss on leaving the icon. The rendered popup was inspected in `outputs/compact-tooltip.png`.

Copy confirmation, 2026-09-06: after clipboard text is verified, the selected message’s Copy icon becomes a matching SVG tick for 1.5 seconds. A new copy restarts the timer; feedback is keyed by conversation and message sequence to survive pagination without moving to another message. The seven message-action tests pass, including exact copied text, only the clicked message changing, and timed restoration. `outputs/copy-tick.png` was visually inspected.

Action selection fix, 2026-09-06: a screenshot of the running app and a failing real mouse-click regression confirmed that QTextBrowser selected the linked image, covering the copy tick. Transcript now handles action-icon mouse gestures directly, activates on release over the same icon, and cancels drags away without selecting content. All 48 native tests pass, including double-clicks, clearing an existing selection and ordinary message-text selection. The corrected mouse-click rendering was visually inspected in `outputs/copy-selection-after.png`; no model calls were needed.

Scrolled-copy regression, 2026-09-06: the previous selection fix called `setTextCursor` even with no selection. Qt scrolled to the old cursor before mouse release, moving the Copy link and cancelling the action. A full click reproduced scroll 4955 → 4 with the clipboard unchanged; all six new scrolled-chat cases fail against the previous installed code. The earlier 48-test claim covered short-chat clicks at the top and did not cover this behavior. The fix skips unnecessary cursor changes and preserves both scrollbar positions while clearing an existing selection, suppressing pagination/follow-tail signals during that operation. All 49 native tests now pass, with exact clipboard, press/release position, tick expiry, existing selection and pagination assertions. `scripts/copy-scroll-proof.py` also passed six desktop cases against the installed native code: XWayland mouse clicks with display scaling, a separate `xclip` clipboard reader, middle/bottom positions and both message roles. Evidence: `outputs/copy-scroll-proof.json` and `outputs/copy-scroll-desktop.png`. This desktop proof uses an isolated preview conversation and makes no model calls; the running Pi UI was reloaded with session and draft preserved.
