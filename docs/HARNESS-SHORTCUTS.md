## Private durable preference contract

`host.describe.capabilities.shortcuts === true` enables authenticated operator
`shortcuts.describe {platform, definitions}` and `shortcuts.edit {platform, edit,
revision}`. Unsupported and restricted inspectors send no preference requests;
restricted HTTP polls carry no global settings revision. The only browser runtime
profile is `web`; visiting-device names select Linux/macOS/Windows keys without
implementing a new OS adapter.

The original pure binding/configuration/persistence protocol is bundled separately
for Node, with a closed reviewed source graph, MIT text and hashed build/source
record. It has no browser, Cordis or native service. The Host seats its original
serialized coordinator on private `settings.json.shortcutBindings`. One document
preserves dormant command overrides and other device profiles; original schema,
revision, conflicts, reservations and accepted-write semantics remain in use.
The Host accepts at most **128 definitions**, **64 KiB serialized catalogue** and
**64 KiB stored document**, validates complete definitions/edits, rejects an
invalid global settings revision, and atomically increments that global revision
while preserving unrelated profile values. Neither models, permissions, memory,
prompts nor agent requests are settings operations here.

Only accepted values feed effective bindings. Missing/corrupt/future/lost/stale/
revoked/malformed replies cannot install a candidate binding or replay a mutation.
An uncertain write disables application shortcut dispatch until a fresh accepted
read; reference diagnostics preserve the visible previous binding and recorder
draft. Operator event polls carry only the settings revision counter, causing
other windows to refresh through the private API. Values never enter observation
journals or restricted event feeds. Catalogue changes invalidate earlier editor
revisions; the original review/retry controls require an explicit user action.
Reload re-reads Host state; external settings-file edits require a guarded Host
restart. Browser origin/port changes do not lose these Host-owned preferences.
