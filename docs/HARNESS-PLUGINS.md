## Status and switches on the overview — October 16

Five cards expose the actual saved enable setting directly: **Web search**,
**Wiki tools & skills**, **Workspace folders**, **Adaptive reasoning** and
**Automatic memory**. The directory and the original detail forms share accepted
settings and revisions. A card switch never commits unrelated unsaved fields;
Wiki reconciles untouched fields while keeping edited fields. Refreshing overview
status also preserves those edits. There is no optimistic On state or automatic
mutation retry. Failed or lost confirmations show **Unconfirmed**, block further
switching, and require an explicit status refresh. Pending application is distinct
from an applied On/Off state. On describes configuration, not external service health.

Memory is labelled **Capture on/off**. Turning capture off also pauses processing;
turning it back on does not resume processing. Its existing detail controls still
own processing. Wiki needs an existing vault before enabling; opening Settings
provides setup. Shared execution changes are disabled during active work, and the
backend retains its guards for jobs/maintenance/revision conflicts. Read-only
inspection does not read privileged settings or expose writable switches.

Prompt library, prompt improvement, model picker and Context are integrated
features without a global disable contract, so their cards say **Built in** rather
than showing a cosmetic switch. **Connected tools** says **Per connection**, and
voice says **On demand**; neither implies a live connection or running service.
This increment does not introduce module unloading or silently change existing
plugin defaults. Status reads alone do not enable a plugin or submit a model/audio
request. Scope remains the private MX review; voice work/later OSes are deferred.

## Prompt library and Improve prompt

Writing exposes both features first. General → Prompt library and the existing
slash-menu entry open the same editor. Saved prompts can be searched, previewed,
created, renamed, edited, explicitly deleted or placed in the composer for review.
The editor provides the clipboard placeholder used by the existing slash workflow.
Saving binds the committed identity/revision; a second edit updates that record.
Refresh keeps local drafts. Concurrent writes surface the existing revision error
without replacing edits or retrying the mutation. Discard and delete require a
visible choice; closing with unsaved changes opens the existing modal primitive's
confirmation, including Escape and return focus. Long editors scroll within the
viewport in the original theme.

The Improve prompt section exposes the existing shared instruction revision,
Save, Reload and defaults. Loading defaults is an unsaved edit. Instructions are
separate from saved shortcuts and conversation system text. Type a draft and use
**✦** beside Send; review the rewrite or Undo before sending. The existing selected-
model, tool-free transaction remains unchanged. This increment fixes missing
editor access, not rewrite semantics, provider capability or latency.

Native Qt and Browser already have their own full library/instruction editors,
backed by the same prompt service when connected to the same library. The new
Harness editor calls that service, not a second store. The private MX review
profiles intentionally use isolated library copies; they are **not live synced**
with the installed Agent/DSH library. Twelve existing DSH prompts are copied to
each review after private snapshots and exact name/body verification. DSH and its
records stay untouched; existing review improvement instructions stay intact.
The running DSH prompt endpoint reports saved prompts but no improvement field.
Installed Agent/DSH service adoption needs separate qualification; source support
must not be reported as installed parity.
