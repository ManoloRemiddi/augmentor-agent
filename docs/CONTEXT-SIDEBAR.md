# Original Context sidebar and placement

The copied dsh-context dashboard now serves the original right sidebar beside
Chat, as well as the center Context tab. Settings → Plugins → Placement uses
its original Tab / Sidebar / All menu. Tab serves the center entry; Sidebar
serves the original sidebar type/guide capsule; All serves both. The preceding
Tab default remains preserved. The original guide’s Context capsule replaces
its Start page with Context; the original title icon, split/close/dock controls
and narrow fullscreen presentation remain in use.

The implementation executes the original public `watchPlacement` and
`watchSidebarContextTab` registrations against the copied MIT tab registry and
an authored UI-only slot bridge. That bridge owns React entries and disposers,
not Cordis/backend services or another agent owner. The center and sidebar use
one recorded Pi data path. Sidebar passes the supplier’s `host: sidebar` flag,
which omits center head cards; compact retained-data/Fleet-unavailable notes
preserve the distinction from live model context. Unknown family data remains
unavailable, with no inferred zero-child figures or new relative backfill.

## Lifecycle and authority

Each sidebar occurrence has a separate scroll key containing Host epoch,
session and tab identity. A marked optional supplier contract preserves the
center tab’s default ledger while restoring the sidebar’s original root
scrollport. Scroll sizing binds the copied dock geometry; supplier CSS and
widgets remain verbatim. Conversation, role or Host changes retire sidebar
occurrences and bytes. Per-session layout metadata remains in the original
validated local store, without serializing content or observation bodies.

The saved placement is a display preference, using the existing revision/CAS,
atomic profile commit and explicit-refresh/no-replay contract. It changes no
prompt, model, routing, tool policy, native conversation or speech setting.
Eight scalar display fields are now writable; Fleet and prefix/suffix remain
disabled. Choosing Sidebar while Context occupies the center returns that seat
to Chat. Settings’ original Open Context action opens the served placement.
Changing placement retires the original registrations without deleting layout
metadata; an unserved saved type uses the original unavailable fallback.

Operator browser-only conversations can view Context in this column. Local
file types/readers remain independently disabled there. Inspector credentials
retain their existing center Context view and read-only defaults, without
private preference reads or local preview access. The inherited operator-only
sidebar does not expose its persisted file layouts to inspectors.

Original File Activity preview links now reach the same actual file reader.
Explicit absolute file resources are bound to the selected Desktop session’s
existing read namespace; foreign session addresses are refused. The opener
reports failure when no preview opens. These explicit UI reads do not upload,
admit a prompt, execute a model tool or infer the contents of a retained result.
[File read/version/size/maintenance contract](HARNESS-FILE-PREVIEWS.md).
