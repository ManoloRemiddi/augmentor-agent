# Recovering interrupted branch publication on Linux

A prepared Fork/Edit can previously save its native child and then fail before
the display journal or metadata is saved. The immutable installed **97897cf**
reproduces this with a real denied display write: after a fresh Host, the same
reserved child remains fenced as an incomplete publication. Its originals are
preserved, but the operation cannot finish. The new Linux publication path finishes
an attested pending child on an explicit same-boundary retry, without another
native branch, provider request, tool execution or child AgentSession.

## Publication and recovery

The existing private [branch identity journal](HARNESS-BRANCH-CONTROLS.md#durable-exact-boundary-recovery--october-13)
still reserves the exact parent/message/mode/child tuple and caps pending identities
at 64. Prepare remains boundary inspection. Linux advertises
`recoverableBranchPublication`; the existing original GUI Fork/Edit controls use
the same prepare/create/settle requests, with no new layout or controls.

Creation asks Pi **1.1.0**'s public in-memory SessionManager to project the selected
ancestry through `createBranchedSession`. Its public header/entries provide the
native payload, including the SDK's label and compaction transformations. The
documented `parentSession` header field records the original source filename;
the native header ID names the child `.jsonl`. Public open/context/discovery APIs
accept that file. This adds no SDK patch/private import or copied branch algorithm.
An empty ancestry retains the existing deferred native-session behavior.

Private `state/branch-publications/<child>.json` stores schema
`augmentor-branch-publication/1`, exact intent, owned staging name and payload
filenames/sizes/SHA-256. The native history, final display journal and metadata
are prepared as private exclusive files in its staging directory, synced, then
attested by an atomic durable manifest. Only that complete manifest authorizes
canonical publication. Native and display files are linked exclusively; metadata
is linked last as the commit point. Existing files are validated rather than
replaced. Parent histories remain untouched.

An explicit retry validates every available original, private directory and link
pair before publishing any missing file. It reuses the stored native header ID,
bytes, selected model/policy and display boundary. A committed child may already
have later user work: its verified original prefixes remain intact and those
later records are retained. No model/tool action is replayed. Startup does not
automatically finish publication. Metadata is never exposed as a partial JSON
copy; hardlink publication makes the complete record visible at once.

After commitment, attested staging aliases and the manifest are removed. A kernel
cleanup failure keeps creation confirmed and leaves remaining private bookkeeping
for a later explicit reconciliation. Unknown extra files remain untouched. An
interruption before a complete manifest leaves unpublished temporary originals;
they do not authorize a canonical child and remain for explicit cleanup. Corrupt,
substituted, linked, foreign or unavailable records fail closed without body
disclosure, truncation or overwrite. Older partial canonical children without an
attested manifest remain fenced: this does not guess their missing contents.

## Data and platform scope

Staged payloads contain the intended ordinary branch history, including submitted
text/tool originals and any saved memory context. They are recovery copies, not
diagnostic payload capture or support-export permission. Pending copies survive
restart; successful cleanup removes the extra aliases. Diagnostic clearing does
not erase them. No external traffic or inference is introduced. Native/display
history and pending-publication cleanup retain their distinct scope.

This filesystem adapter is Linux-only, matching the MX-first delivery instruction.
Windows/macOS retain their existing durable identity and incomplete-publication
guard; their atomic publication adapters and physical qualification remain open.
Original DSH GUI/CSS, supplier licences/dependencies and Qwen/Breeze/ASR/VAD
placement remain unchanged. Full migration, ambiguous legacy repair, live/privacy,
public distribution and broader platform/CI gates remain open.
